# P-064: Build public landing, welcome, and demo entry pages

## Objective

Create the first real public-facing landing surface for the rewrite so
prospective users can understand what the product does, see whether it fits
their setup, preview it safely, and move into the beta-access flow without
confusion.

## Scope

- Build the first public landing page for unauthenticated visitors
- Include clear messaging for:
  - what the product helps users understand
  - who the current beta is for
  - supported provider/setup expectations
  - privacy/trust expectations at a high level
- Add clear calls to action for:
  - request beta access
  - sign in if already approved
  - open the read-only demo experience
- Define or implement the first lightweight welcome structure around that
  landing page so public users are not dropped into raw auth or request-form
  screens without context
- Make sure the landing page works cleanly on desktop and mobile

## Out of Scope

- Deep marketing-site content such as long-form feature pages, blog/news, or
  SEO-heavy content architecture
- Pricing and subscription packaging
- Reworking the approved-user authenticated app shell

## Acceptance Criteria

- Unauthenticated users land on a coherent public page rather than a bare form
  or auth prompt
- The page explains the product, beta scope, and supported setup clearly enough
  that users can self-select before requesting access
- Demo, sign-in, and beta-request entry points are all easy to find
- Public copy sets realistic expectations about provider support and current
  beta shape
- Desktop and mobile layouts feel intentional and production-ready
